# Local validation stack

Runs the dataplane on its own — no Kubernetes, no operator — against a Mailpit
instance standing in for the target SMTP server.

```bash
make compose-up      # generates certificates, builds the image, starts everything
make compose-down
```

| Endpoint | Address | Notes |
|---|---|---|
| Submission (STARTTLS) | `localhost:1587` | AUTH is only offered once TLS is up |
| Submissions (implicit TLS) | `localhost:1465` | |
| Mailpit UI | http://localhost:18025 | where relayed mail lands |

Account: `app1` / `demo-password`.

Certificates are signed by a throwaway CA regenerated by `make compose-certs`;
point your client at `deploy/compose/certs/ca.crt`. Two certificates are served,
`mailout.test` and `alt.mailout.test`, so SNI selection can be observed:

```bash
echo QUIT | openssl s_client -connect localhost:1465 -servername alt.mailout.test \
  -CAfile deploy/compose/certs/ca.crt 2>/dev/null | openssl x509 -noout -subject
# subject=CN=alt.mailout.test
```

Sending a message, with the CA trusted:

```bash
swaks --to dest@example.test --from app@example.test \
      --server localhost:1587 --tls --tls-ca-path deploy/compose/certs/ca.crt \
      --auth-user app1 --auth-password demo-password
```

## Virus scanning

`clamav-milter` sits between the gateway and `clamd`, wired as
`tcp://clamav-milter:7357` in `gateway.yaml`. The first start downloads the
signature database (a few minutes); the gateway waits on clamd's healthcheck.

A clean message comes out with the scanner's headers applied by the gateway:

```
X-Virus-Scanned: clamav-milter 1.5.4 at ...
X-Virus-Status: Clean
```

An EICAR test file is refused at DATA time, with the scanner's own reason
relayed to the client:

```
SMTP error 550: 5.7.1 Malware detected: Eicar-Signature
```

`failOpen` is off, so if the scanner is unreachable the gateway answers 451 and
the client retries — mail never goes out unscanned.

The same scenarios run unattended as Go tests: `make test-e2e`.
